## 需求概述

建设一套可持续扩展的工具平台，逐步提供多个面向硬件开发和日常工作的实用工具。用户可以通过网站发现、访问和使用单个在线工具，也可以按需要下载适合本机运行的工具。首期目标是提供浏览器串口助手，让用户连接电脑上的串口设备并在网页中完成串口调试；后续逐步探索在线编程、在线调试等工具，形成类似“平台 + 小程序”的工具集合。

## 使用场景与用户

- 硬件开发者使用网页工具连接本机串口设备，进行串口收发与调试。
- 用户通过统一网站发现并打开所需工具，不必为每个工具单独寻找入口。
- 随着工具类型增加，用户仍能从统一平台访问在线工具，或获取可下载使用的工具。

## 功能需求

### P0 - 首期必须实现

- [ ] 工具入口：用户打开网站后能看到平台名称、可用工具及其用途，并能进入串口助手。
- [ ] 浏览器串口连接：用户可查看浏览器支持的串口设备并主动选择、授权和连接设备。
- [ ] 串口参数配置：用户可设置常用串口通信参数，并在连接前完成配置。
- [ ] 串口数据交互：连接成功后可发送数据，并实时查看从设备接收的数据。
- [ ] 连接控制：用户可查看连接状态，并主动断开串口设备。
- [ ] 基础可用性提示：在浏览器或操作系统不支持 Web Serial、用户未授权或设备连接失败时，页面应说明当前状态及可采取的操作。

### P1 - 平台与工具的重要能力

- [ ] 工具目录：按类别浏览可用工具，查看工具名称、简介、运行方式和状态。
- [ ] 工具详情与访问：用户能进入单个工具页面，并明确其在线使用或下载方式。
- [ ] 串口调试辅助：支持清空接收区、暂停/继续显示、滚动查看及常见文本/十六进制数据显示方式。
- [ ] 串口数据记录：用户可按明确操作复制或导出本次调试记录。
- [ ] 下载型工具入口：平台可展示本地安装或独立运行工具的下载信息。

### P2 - 后续扩展方向

- [ ] 在线编程工具：评估并提供类似 K230 在线编程的浏览器开发体验。
- [ ] 在线调试工具：评估并提供类似 DAP 在线调试的硬件调试能力。
- [ ] 工具分类、收藏或最近使用等平台效率能力。
- [ ] 随工具数量和使用场景增长，评估账号、同步和权限等能力。

## 非功能需求

- **兼容性：** 串口助手必须清晰说明浏览器、操作系统与安全上下文方面的使用要求；能力不支持时不能呈现为已连接或可用。
- **安全与隐私：** 串口设备访问应由用户显式发起和授权；数据默认只用于当前调试会话，是否保存、上传或同步必须由用户明确知情并控制。
- **可靠性：** 连接、断开、设备拔出、权限拒绝和页面错误等状态应可识别，不能让用户误判数据仍在传输。
- **可扩展性：** 新增工具时应保持统一的发现和进入体验，同时允许工具拥有适合自身用途的独立交互界面。
- **易用性：** 核心连接与收发流程应清晰可见，首次使用者能理解连接状态、串口参数及错误提示。
- **部署目标：** 最终平台计划部署在服务器上，用户通过网站访问；服务器部署、域名、运维和下载分发方案尚待方案设计确认。

## 边界与约束

- **首期范围：** 统一工具入口与浏览器串口助手的核心连接、配置、收发和状态反馈。
- **暂不包含：** 首期不要求实现 K230 编程、DAP 调试、完整用户账号体系、云端数据同步、工具市场结算或多人协作。
- **浏览器限制：** 网页访问本机串口依赖浏览器提供的设备访问能力和用户授权；需验证目标浏览器、操作系统及部署环境，不能假设所有浏览器均支持。
- **硬件依赖：** 串口助手需要用户本机存在可用串口设备及相应驱动；不同 USB 转串口芯片和设备行为可能不同。
- **参考产品：** 波特律动串口助手、嘉立创 K230 在线编程工具、嘉立创 DAP 在线调试。参考其产品体验和工作流，不默认复制其实现或功能范围。
- **待定事项：** 平台名称与视觉风格、首期浏览器/操作系统范围、串口数据格式和高级功能、是否支持离线使用、下载工具的操作系统范围、服务器部署方式及账号需求。

## 验收标准

### 工具入口

- Given 用户访问平台首页，When 首页加载完成，Then 页面展示平台工具入口及串口助手入口，并可进入串口助手。
- Given 一个工具尚未开放，When 用户查看工具目录，Then 工具状态应明确标记为规划中或不可用，不能表现为可正常启动。

### 浏览器串口连接

- Given 用户使用受支持的浏览器并连接了可用串口设备，When 用户主动点击连接并选择设备、授权，Then 页面显示连接成功及当前设备状态。
- Given 用户拒绝授权或浏览器不支持串口访问，When 用户尝试连接，Then 页面显示明确原因和可行的下一步，不显示虚假的连接成功状态。
- Given 串口已连接，When 用户断开连接或设备被拔出，Then 页面更新为断开状态并停止向该连接发送数据。

### 串口参数配置

- Given 用户尚未连接设备，When 用户选择波特率及其他支持的通信参数并连接，Then 连接使用已选参数。
- Given 用户输入无效或当前状态不允许修改的参数，When 用户尝试连接或更改参数，Then 页面阻止无效操作并说明原因。

### 串口数据交互

- Given 串口连接成功，When 用户输入并发送文本或支持的数据格式，Then 页面按所选格式发送数据并提供发送结果反馈。
- Given 设备向串口发送数据，When 数据被浏览器接收，Then 接收区按选定显示方式追加内容，且用户可识别接收内容和连接状态。
- Given 用户主动清空接收区，When 清空操作完成，Then 仅清除页面当前显示记录，不影响设备状态或设备端数据。

### 调试记录与数据控制

- Given 用户执行复制或导出操作，When 操作完成，Then 记录仅包含用户明确选择的本次调试数据，且平台不会在未告知的情况下上传串口内容。

## 关键假设与待确认

- 首期可用性以支持 Web Serial 的桌面浏览器为主；具体浏览器和操作系统版本需在技术方案阶段明确。
- 用户所说的“下载和使用”可能指下载独立应用，也可能指下载工具文件或本地离线包，首期暂按平台展示下载入口处理。
- “工具系统类似微信和小程序”指统一入口与多个相对独立的工具体验，不代表首期需要账号、支付、社交或小程序运行时。
- 下一阶段需优先确认串口助手的目标用户环境、必要的串口协议/显示能力，以及第一阶段是否只建设网站与串口助手。
