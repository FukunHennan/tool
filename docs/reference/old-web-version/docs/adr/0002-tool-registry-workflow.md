# ADR-0002：采用工具注册中心与图执行模型

- 状态：已接受
- 日期：2026-07-21

## 背景

PC Toolbox 后续会加入更多工具，并希望提供类似 Node-RED 的节点编排方式。如果每个工具分别实现页面、节点面板和执行逻辑，平台会快速出现重复代码和能力不一致。

## 决策

建立集中式 `ToolRegistry`。所有可编排能力通过统一节点定义注册，工作流编辑器和执行器只依赖注册协议。

第一版使用 React Flow 作为图形画布，工作流存储为版本化 JSON，浏览器运行时使用拓扑排序执行有向无环图。

独立工具和工作流节点共享底层服务，例如串口工具与串口节点共享 `SerialService`。

## 结果

收益：

- 新工具注册后可自动进入节点库。
- 配置 Schema、画布信息和执行器保持一致。
- 工作流执行与 React UI 解耦。
- 未来可以增加浏览器、本地 Agent 和云端多运行时。

代价：

- 需要维护稳定的节点类型和文档版本。
- 跨工具数据类型必须建立明确契约。
- 事件流、循环和分布式执行需要后续专门设计。

## 当前限制

- 只支持有向无环图。
- 工作流只保存在本地浏览器。
- 暂无撤销、导入导出和端口类型校验。
- 串口授权仍需在串口工具中由用户完成。
