# 测试策略

## 当前自动化命令

```bash
pnpm test        # 单次运行全部 Vitest 单元测试
pnpm test:watch  # 监听源码与测试变化并增量重跑
pnpm typecheck   # 运行 TypeScript 严格类型检查
pnpm check       # 依次运行类型检查、单元测试和生产构建
```

当前单元测试覆盖 HEX 格式转换、串口控制器、工作流执行与文档处理、ESP eFuse 安全摘要解析，以及 ESP 芯片/通讯信息分析。组件测试、Mock E2E 与 lint 仍是后续门禁目标，尚未提供对应命令。

## 1. 测试金字塔

### 单元测试

重点覆盖：

- HEX 文本与 `Uint8Array` 互转。
- 文本编码与换行追加。
- CRC/校验算法。
- 帧解码的半包、粘包和错误恢复。
- 连接状态机的合法与非法转换。
- 日志容量限制与统计计算。

协议测试必须是确定性的，不依赖浏览器或真实串口。

### 组件测试

使用 Mock Transport 验证：

- 不支持 Web Serial 时的提示。
- 不同连接状态下按钮是否正确启用。
- 参数校验和发送格式。
- 接收数据显示、暂停和清空。
- 断线错误提示与再次连接流程。

### 端到端测试

浏览器自动化只覆盖不依赖系统串口选择器的路径：Mock 模式、界面导航、本地配置和导出。真实 Web Serial 权限弹窗不作为普通 CI 的稳定依赖。

### 真机测试

使用已知测试设备人工执行：

1. 首次授权并连接。
2. 正确参数下双向收发。
3. 错误波特率下的表现。
4. 连接期间拔出设备。
5. 端口被其他软件占用。
6. 高频连续接收至少 30 分钟。
7. 手动和定时发送并发操作。
8. 断开后重新连接。
9. 页面刷新和浏览器休眠恢复。
10. 日志导出并核对字节数。

## 2. 性能基线

具体数值需根据设备吞吐量确认。初始目标：

- 持续接收时界面保持可操作。
- 显示更新批处理，不因单字节消息造成高频 React 渲染。
- 控制台内存记录达到上限后保持稳定。
- 解析器面对非法长度时不会无限扩张缓冲区。

## 3. 发布门禁

合并到主分支前至少要求：

- lint、类型检查、单元测试通过。
- 生产构建成功。
- 核心 Mock E2E 通过。
- 涉及 Web Serial 资源生命周期的改动完成真机冒烟测试。
- 技术文档与实现一致。
